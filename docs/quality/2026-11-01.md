# Quality check, 2026-11-01 rules (checked 2026-11-12)

The owner's 10 rules, checked against the M1 code on Windows 11 with Go 1.26.10 and a local
PostgreSQL 17.11. The race detector needs cgo, which this machine lacks; CI runs every test with
`-race`.

| # | Rule | Status | Evidence |
|---|---|---|---|
| 1 | Assume every call can fail | pass | External calls are PostgreSQL (pgx) and, in `scripts/local-postgres.sh`, curl. Every pgx call takes a context; `connect` sets a 10 s connect timeout (`cmd/osm/main.go`); every runner transaction sets `lock_timeout` and `statement_timeout` (`run.go` `once`); lock timeouts (SQLSTATE 55P03) are retried with doubling backoff, jitter and a cap, at most `-retries` times (`run.go` `inTx`), proven by `TestPGLockTimeoutRetriesAreBounded`. curl uses `--max-time` and `--retry 3`, and the download is SHA-256 checked. Every error is returned with context. Ignored results, each commented: the deferred `tx.Rollback` after commit (a no-op), progress-line writes in `logf`, connection close in test cleanup. |
| 2 | Writes safe to retry | pass | Expand: `ADD COLUMN IF NOT EXISTS`, `CREATE OR REPLACE FUNCTION/TRIGGER`, and the state row in the same transaction. Backfill: each batch and its cursor commit together, and the update skips rows already in sync (`IS DISTINCT FROM`). Contract: the step number is saved in the same transaction as the step. State is an upsert. Tests: second expand and second contract are no-ops; backfill stopped after 3 batches resumes and updates exactly 3,000 rows in total. |
| 3 | No race conditions | pass | Each runner transaction takes `pg_advisory_xact_lock` for the change and re-reads the state inside it (`run.go` `once`), so two runners cannot do the same batch: `TestPGConcurrentBackfillRunnersDoEachBatchOnce` (two runners, 3,000 rows updated in total). The concurrent-writer test reads `writerErr` only after `wg.Wait()`. No shared mutable state in the analyser. `-race`: CI only. |
| 4 | Don't trust the clock | pass | Durations use `time.Since` on `time.Now` (monotonic) in `Run`; `osm_state.updated_at` is `timestamptz` set by the server's `now()` and returned in UTC (`load`), checked in the end-to-end test. Nothing is ordered by wall-clock time; progress uses the key cursor and step number. |
| 5 | Read before changing | pass | APIs used exist in pgx v5.12.0 (`pgx.ParseConfig`, `ConnectConfig`, `pgconn.PgError.Code`) and PostgreSQL 17 (`CREATE OR REPLACE TRIGGER`, `pg_advisory_xact_lock`, `current_setting(name, true)`), all exercised by the server tests. Environment variables read: `OSM_DATABASE_URL` (CLI), `OSM_TEST_DATABASE_URL` (tests), `OSM_PG_PORT` (local server script); all three are documented in the README. |
| 6 | Never break compatibility | pass | This is the project's subject: the plan never renames or retypes in place; both columns are kept in sync until contract, which runs only after switch. `TestPGExpandContractEndToEnd` writes with "old code" during expand to switch and with "new code" after switch. The only new database object outside the plan is `osm_state` (created if missing). |
| 7 | One source of truth | pass | Progress lives only in `osm_state`; the spec hash stored with it refuses a run under a changed spec (`ErrSpecChanged`, tested). The stats file is a copy of catalog numbers: the README says where they come from (`pg_class.reltuples`, `information_schema.columns`) and that unknown tables count as large. Go 1.26.10 in CI, README and results; `go.mod` states the minimum (`go 1.25.0`, set by pgx). |
| 8 | Small changes, no secrets, validate input | pass | No secrets: the CI database uses `trust` auth inside a job-local container; the DSN comes from an environment variable, not a flag. Inputs validated: spec (strict JSON, identifier pattern, type pattern, expression checks, ranges), stats file (strict JSON, no negative rows), SQL files (8 MiB cap, unterminated quotes refused), CLI flags (ranges). One dependency: pgx (the PostgreSQL driver). |
| 9 | Tests that can actually fail | pass | No skips except the documented "no server" skip, which `make test-pg` and `.tmp/check.sh` turn into a failure. No tautologies. Mutation check below: 13 of 13 killed. Empty input, invalid input and failure paths are covered for each entry point (Split, Analyze, LoadStats, ParseSpec, Run, CLI). |
| 10 | Re-verify | pass | `bash .tmp/check.sh` twice: gofmt clean, `go vet` clean, 38 tests passed (137 with subtests), 0 skipped, govulncheck "Your code is affected by 0 vulnerabilities", `CHECK PASS`. `python .tools/audit_repo.py online-schema-migrations`: OK. CI: not run yet (no push). |

Known limitations (documented in the README): rules target PostgreSQL 14 to 17 and are server-checked
on 17.11 only; the four `CONCURRENTLY`/`VACUUM FULL` forms are not server-checked; row counts come
from a stats file; govulncheck lists GO-2026-6859 in Go 1.26.10's net/http as present but not
called.

## Mutation check

Hand mutations applied one at a time by `.tmp/mutate.sh` (perl substitution, `go test -count=1
-failfast` on the package, then the file restored from a copy at once), with the local PostgreSQL
running so the server tests count. After the run, `go build` and `gofmt -l` confirmed every file
was restored.

| Function | Mutation | Killed? | Killed by |
|---|---|---|---|
| `analyze.Conflicts` (matrix) | SHARE no longer conflicts with ROW EXCLUSIVE | yes | `TestStatementRules` (CREATE INDEX blocks writes) |
| `analyze.BinaryCoercible` | wider-varchar check `>=` becomes `<=` | yes | `TestStatementRules` |
| `analyze.callsVolatile` | always false | yes | `TestStatementRules` (volatile default rewrites) |
| `analyze.large` | `rows >= MaxRows` becomes `>` | yes | `TestMaxRowsThreshold` |
| `analyze.judge` | `SET LOCAL lock_timeout` ignored | yes | `TestStatementRules` |
| `analyze.alterColumn` | validated NOT NULL check ignored | yes | `TestValidatedNotNullCheckAvoidsScan` |
| `analyze.addColumn` | NOT NULL without default not flagged | yes | `TestStatementRules` |
| `sqlscan.Split` | dollar quotes not recognised | yes | `TestSplitRespectsQuotesCommentsAndLines` |
